## First public proof: a synthetic demonstration

Working title: A bank assistant that must not turn a document instruction into a data-export permission.

Use fictional records and a local test workflow. Show a baseline failure in an intentionally vulnerable demonstration, then implement controls and rerun the same evaluation. Publish only observed results, the test procedure and limitations.

Demonstration outputs:
- A simple architecture and threat model.
- The test input and observable action taken or rejected.
- Before-and-after logs, using synthetic identities and records.
- A brief account of what the controls address and what remains untested.

A demonstration is not a bank audit and must be labelled accordingly. No bank infrastructure is involved.

Draft review questions:
1. Does each agent have an identifiable owner and service identity?
2. Are permissions limited to the workflow's actual needs?
3. Are retrieved documents treated as untrusted content?
4. Are sensitive data and export destinations constrained?
5. Are high-impact actions authorized outside the model's own judgment?
6. Are tool parameters and action outcomes validated?
7. Can a reviewer reconstruct consequential actions without exposing secrets in logs?
8. Can credentials and tasks be revoked or stopped promptly?
9. Are tool and dependency changes assessed before release?
10. Are adversarial evaluations repeated after material changes?

Use NIST's identity work and OWASP's agentic security resources as references for developing the methodology.[2][7] These questions are an initial research outline, not a validated assurance standard.
