## Quality bar — evidence, not assertion

- **Lighthouse mobile ≥ 90.** Measured locally against the bundled Chromium
  on every gated page. Scores were 100 / 100 / 100 / 100 (performance,
  accessibility, SEO, best practices) on the board, NEXT, SOP, the ORIGICAST
  gate and success pages, and the AGB / Datenschutz pages. Zero CLS, zero
  console errors, LCP 0.6–0.9 s, pages 4–26 KiB. `ci/lighthouse.py` fails the
  build under 0.90, on any CLS, or on any console error. First runs found real
  defects and they were fixed: the noindex meta blocked the SEO gate (removed
  for these unlinked views); the CHF 1 «Open» chip failed contrast on NEXT/SOP
  (white-on-gold link fixed).
- **No external fonts.** The HQ views drop external stylesheet/preconnect links
  from the canon head (logged as `boot5 WARN`) and use system fonts; the
  ORIGICAST pages never had any. Asserted in `test_board_compose`,
  `test_next_sop_compose`, `test_origicast` and every e2e spec.
- **Stranger e2e (Playwright), mobile + desktop.** `e2e/tests/`: the board
  renders the counter and rows in under 1 s with no external request; the
  click queue is first on NEXT and SOP and search filters; ORIGICAST goes
  gate → door → CHF 1 paid → success-with-reference with zero console errors.
- **Copy is de-CH.** `ss` not `ß` (asserted), «Sie», `CHF 1'390` apostrophe
  thousands. All guest text is in `app/templates/messages/` per the repo rule.
- **Legal on every page.** Impressum existed; AGB and Datenschutz are new
  (`/agb/`, `/datenschutz/`), cookie-free, linked from every ORIGICAST page
  and asserted in the e2e.
- **Ops.** `GET /healthz` answers without the database; every unhandled 5xx
  posts one JSON alert to the Engine Error Alerts workflow
  (`ERROR_ALERT_WEBHOOK_URL`) and returns a plain 500. Covered in
  `test_error_alerts` and `test_origicast`.
- **Publish integrity.** `scripts/publish_verify.py --live <url>` hashes every
  served view against the repo render (canon blocks, the build stamp and the
  title normalised out) and exits non-zero on the first mismatch. CI runs it
  against the freshly built `/srv`.

## Honest gaps — what a human still owns

1. **No stranger has paid on the live domain yet.** The CHF 1 flow is proven
   end to end against `ci/stub_stripe.py`, not against Stripe. Before
   ORIGICAST is flipped `live: true`, Marcin runs the real CHF 1 test on
   `www.startend.ch/origicast/` and refunds it — SOP `chf1-test`. Until then
   `live` stays `false` and the board counter does not count it.
2. **The board still depends on canon at boot.** The composed board reads
   `BOARD_HTML` from the canon webhook; if canon is down, boot falls back to
   the board already on disk. That fallback is tested, but a first-ever boot
   with canon down and no prior `/srv` would leave the board unwritten. Not a
   regression — the canon-backed views always behaved this way.
3. **`checklist.json` and `sop.json` are hand-maintained.** The `live` flags
   reflect intent as of today, not a probe of each door. Keeping them true is
   SOP `update-checklist`; nothing auto-verifies that a `live: true` row is
   actually payable.
4. **`ORIGICAST_LIVE` gates rendering, not a real catalogue.** Season / Hour /
   Keep, when enabled, redirect back to the door anchor — there is no product
   behind them yet. That is deliberate for this contract (prove the door and
   the CHF 1 test); the offers are the next contract.
5. **Lighthouse numbers are from this environment.** CI runs the same gate on
   GitHub's runner; a cold runner can score a few points lower on performance.
   The 0.90 floor leaves headroom, but if CI performance flakes, that is the
   first thing to look at, not a code regression.

## Risk notes

- **Money routing.** ORIGICAST has no Stripe Price id (CHF 1 uses
  `price_data`), so its only routing signal is `metadata.venture=origicast`.
  An event without that metadata is acknowledged and stored nowhere rather
  than guessed into the wrong table — the existing venture-routing rule, now
  covered for origicast in `test_origicast`.
- **No secrets added.** Every new URL (canon, bus, HQ Mail, error alerts) is
  read from the environment; `.env.example` documents each. `test_sop_json_*`
  asserts no webhook URL leaked into `boot/data/`.
- **Age gate is functional, not identity.** It is a self-declared 21+ check in
  the signed session cookie, no tracking — appropriate for a door, not a
  substitute for real age verification if that is ever required by law.
