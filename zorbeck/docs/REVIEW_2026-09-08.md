## What I would flag in someone else's PR

1. **The product behind the promise is not in this repo.** The page and the
   mail promise a first report within 24 hours and 30 days of alerts. The
   scraping/comparison that produces them is not built here; today it is a
   promise the operator has to keep (manually or in n8n) from the `paid` lead
   row. The AGB therefore promise a full refund when no report arrives. This
   is the biggest gap between «sellable» and «self-serve».
2. **Price is an assumption.** `ZORBECK_PRICE_CENTS` defaults to 4900
   (CHF 49). No contract stated a price; the number is a placeholder that is
   easy to change in the environment and shows everywhere consistently (page,
   FAQ, CTA, checkout). Decide the real price before outbound.
3. **Confirmation-sent flag relies on Stripe accepting a metadata update on a
   completed Checkout Session.** Stripe documents `POST /v1/checkout/sessions/:id`
   with `metadata`; if a future API version rejects it, the code logs a
   warning and the in-process set still prevents duplicates within one
   instance. Worst case across instances: a second identical confirmation
   mail. Verified against the stub, not yet against live Stripe test mode.
4. **Lead rows are best effort.** A failed `SIGNUP_WEBHOOK_URL` post is
   alerted, not retried; the paid session still exists in Stripe, so nothing
   is lost, but the n8n table can lag reality.
5. **`ZORBECK_STUB` must never be set in production.** It is a single
   environment variable away from a fake checkout that «pays» anything.
   `/healthz` exposes `stub: true` so a monitor can catch it; a hard refusal
   to start when `stub` is on and `PUBLIC_BASE_URL` is not localhost would be
   safer. Not done to keep the CI path identical to production.
6. **Single-process assumptions.** In-memory `confirmed_sessions`; fine for
   one Railway instance, which is the deployment today.
7. **The legacy `/signup` endpoint is kept** (wave 1 free signup) so no old
   link breaks; it writes a `signup` lead row and answers in German. It is
   not linked from the page and could be removed once the old form is gone.
